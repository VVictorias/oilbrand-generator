# Oilbrand — полный генератор названий

Готовая база: `data/brands.sqlite`, **23 847 260** названий. Полный охват пространства A–Z длиной 4–6: **321 254 128** комбинаций. Списков «лучших» и ограничения количества сохранённых результатов нет.

## Скачать полную базу из GitHub Releases

Исходники находятся в этом приватном репозитории. Файл SQLite не хранится в Git-истории из-за размера. **Полная база, все 23 847 260 названий**, доступна в [релизе v1.0.0](https://github.com/VVictorias/oilbrand-generator/releases/tag/v1.0.0).

1. На странице релиза скачайте `brands.sqlite.gz` (около 1,59 GB) и при необходимости `SHA256SUMS.txt`.
2. В папке проекта распакуйте базу с проверкой SHA-256:

```sh
python3 restore_database.py /полный/путь/к/brands.sqlite.gz
python3 brandgen.py serve
```

Результат — `data/brands.sqlite`, 6,09 GB. Для распаковки нужен соответствующий запас диска. Скрипт не перезаписывает существующую базу. Альтернатива загрузке — полностью пересоздать ту же базу командой `python3 brandgen.py generate`.

## Открыть интерфейс

Из папки проекта:

```sh
python3 brandgen.py serve
```

Откройте <http://127.0.0.1:8765>. Остановка: Ctrl+C. Для другого порта: `python3 brandgen.py serve --port 8767`. Для просмотра готовой базы нужен только Python 3.10+ с SQLite; сторонних Python-пакетов нет. Сервер слушает только 127.0.0.1, работает без интернета.

macOS: можно запустить `Открыть каталог.command` двойным щелчком. Он запустит сервер и откроет браузер. Если порт занят, используйте команду с другим портом.

Поиск по подстроке и точному названию, длина, начало/конец, диапазоны количества гласных/согласных, структура, предполагаемые слоги, исключение сочетаний/окончаний и фонетические признаки объединяются. Изменение этих фильтров **не меняет базу** и не требует перебора. Кнопка «Применить» фиксирует фильтры. «Избранное» показывает понравившиеся варианты с текущими фильтрами; «Сбросить» очищает фильтры.

Страница содержит 100 строк; «Далее»/«Назад» используют курсор по значениям индекса, без глубокого OFFSET. Это ограничение размера страницы, а не набора кандидатов. Точное количество найденных строк считается отдельно кнопкой: сложный запрос на десятках миллионов строк может потребовать времени. Поиск произвольной подстроки и исключения подстрок могут сканировать значительную часть базы.

Звёздочка сохраняется в SQLite. Квадратные флажки выбирают строки для экспорта и сохраняют выбор при перелистывании в рамках открытой страницы приложения. «Вся текущая выборка» экспортирует **все** строки по применённым фильтрам, независимо от страницы. «Отмеченные строки» экспортирует именно выделенные ID, в том числе с других страниц. CSV создаются в `exports/<идентификатор>/`, ссылки появляются после завершения. Не закрывайте сервер до конца экспорта. Файлы сохраняются после перезапуска, история заданий и ссылки интерфейса — в памяти текущего сервера. Ошибка диска будет показана явно; незавершённый экспорт можно повторить новым заданием.

## Правила

`config/rules.json` — редактируемый JSON. Начальная конфигурация:

- A–Z, длины 4, 5, 6; гласные **AEIOU**, Y считается согласной;
- Q, W, X, J запрещены;
- максимум 2 согласных, 2 гласных и 2 одинаковые буквы подряд;
- `forbidden_substrings`, `forbidden_suffixes`, `stop_dictionary_files` пусты, поскольку конкретные списки не были предоставлены;
- `analysis.warning_suffixes` — окончания, которые **отмечаются**, а не запрещаются;
- `analysis.transcription` и `analysis.ambiguous_letters` задают вспомогательный анализ.

`max_identical_run: 2` означает запрет трёх одинаковых букв подряд. Все буквенные правила указываются в верхнем регистре. Лимиты 0–6; длины 1–6 поддержаны для тестирования, итоговая конфигурация использует только 4–6.

Стоп-словарь — UTF-8 TXT, по одному точному названию на строку. Пустые строки и строки с `#` в начале игнорируются; пробелы по краям удаляются, регистр приводится к верхнему. Только A–Z; неверные строки вызывают явную ошибку. Путь в `stop_dictionary_files` считается относительно файла конфига. Словарь не запрещает подстроки: BEKA не удаляет BEKAB. Снимок правил, полный объединённый стоп-список, SHA-256 исходных словарей и отпечаток конфигурации записаны в `metadata` и `rules` базы.

Для новых жёстких правил создайте новую базу:

```sh
python3 brandgen.py generate --config config/rules.json --db data/another.sqlite
```

Изменённый конфиг не допускается при возобновлении существующей базы. Более строгие ограничения на уже сохранённые данные можно применять поиском, экспортом, API или SQL без нового перебора. Ослабление первоначальных запретов требует новой генерации: отклонённые строки в базе не хранятся. Изменение определения гласных/транскрипции также требует новой генерации для пересчёта признаков.

## Генерация и продолжение

Нужен компилятор C++17 (`clang++`, либо переменная `CXX=g++`) и библиотека SQLite с заголовками. На этом Mac они уже доступны. Нативный исполняемый файл автоматически собирается в `work/generator`. При переносе на другую ОС удалите эту папку, чтобы пересобрать бинарник. На Linux установите средствами своей системы компилятор и заголовки SQLite.

```sh
python3 brandgen.py generate
```

Повтор той же команды продолжает расчёт. Блок — одна длина и первая буква, всего 78. Данные блока и его checkpoint фиксируются одной транзакцией. Остановка до COMMIT откатывает только текущий блок; завершённые блоки сохраняются. Индексы строятся после генерации и также могут быть достроены повторным запуском. Одновременно запускайте только один генератор для одного файла SQLite. Не меняйте таблицы `candidates`, `rules`, `checkpoints`, `metadata` вручную во время расчёта.

Рекурсивный обход последовательно рассматривает A–Z. Если префикс уже нарушил правило, все его продолжения математически недопустимы: они учитываются в статистике весом `26^(оставшихся позиций)`, без создания строк в памяти. Отсечение не использует частотность, словари естественного языка, субъективную оценку или случайность. Каждое допустимое имя записывается сразу. Идентификатор — взаимно однозначный порядковый номер в полном пространстве A–Z с учётом длины; `UNIQUE(name)` дополнительно запрещает дубликаты.

Нативный перебор без записи занимает 0,35 с, запись 23,85 млн строк — 30,12 с, полный запуск с индексами — 110,97 с на этом компьютере. Используется один писатель SQLite: узкое место — запись и индексы, а не перебор. Параллельные писатели в этот же файл не включены. HTTP-запросы выполняются отдельными потоками, CSV — фоновым потоком; выгрузки последовательно обслуживает один работник, чтобы не размножать нагрузку на диск. В память не загружается набор кандидатов: только текущая строка, курсор страницы, настройки, стоп-словарь и ограниченный кэш SQLite.

Готовая база с индексами занимает **6 091 849 728 байт** (~6,09 GB, 5,67 GiB). Для нового запуска и индексации оставьте запас диска; полный CSV тоже может занимать несколько гигабайт. В отсутствие места операция завершится с ошибкой, а уже завершённые транзакции останутся в SQLite. Для копирования базы остановите сервер и генератор; не копируйте только `.sqlite`, пока рядом есть незавершённый WAL.

## CSV через командную строку

Все строки, части по миллиону:

```sh
python3 brandgen.py export --out exports/full --split 1000000
```

Произвольное сочетание поддерживаемых фильтров:

```sh
python3 brandgen.py export --out exports/filtered --split 1000000 --filters '{"length":6,"prefix":"MO","suffix":"A","vowels_min":2,"exclude":"ZZ,HH","sort":"name","direction":"asc"}'
```

Поддерживаются `q`, `exact`, `length`, `prefix`, `suffix`, `vowels`, `consonants`, `vowels_min/max`, `consonants_min/max`, `structure`, `syllables`, `exclude`, `exclude_suffix`, `no_repeats`, `warning_only`, `phonetics`, `favorites`, `ids`, `sort`, `direction`. Несколько исключений разделяются запятыми. `sort`: name, length, vowels, consonants, structure; направление asc/desc. Экспорт пишет UTF-8 с BOM и заголовками во все части, не перезаписывает существующий файл. Используйте новую выходную папку при повторе экспорта.

## Поля и анализ

`name`, `length`, `first`, `last`, `reversed`, `vowels`, `consonants`, `structure`, `transcription`, `syllables`, `repeated_letters`, `repeated_pairs`, `warning_suffixes`, `phonetics`, `ambiguous`, `id`. При CSV/HTTP дополнительно есть `favorite`.

`transcription` — явная побуквенная русская транслитерация, **не** достоверное произношение иностранного слова. `syllables` — число групп соседних гласных (приблизительная оценка). Повторы букв и биграмм включают пересекающиеся позиции; формат `A:3` или `AB:2`. Фонетические признаки: `no_vowels`, `consonant_cluster`, `vowel_cluster`, `ambiguous_reading`, `repeated_letters`. Эти поля никогда не удаляют строки. Домены и товарные знаки не проверялись.

Индексы: уникальное имя, (длина, имя), (первая буква, имя), (последняя буква, имя), перевёрнутое имя для окончаний, (структура, имя), (гласные, имя), (согласные, имя). Сложные произвольные исследования доступны обычным SQL к полной базе.

## Проверки

```sh
python3 -m unittest discover -s tests -v
python3 brandgen.py verify
```

`verify` выполняет SQLite integrity_check, независимый подсчёт конечным автоматом/динамическим программированием, проверку жёстких правил, числа строк и баланса статистики. На полной базе это заняло 133,77 с.

Сплошной независимый аудит классификации букв, идентификаторов и полей:

```sh
clang++ -O3 -std=c++17 src/audit.cpp -lsqlite3 -o work/audit
./work/audit data/brands.sqlite
```

HTTP-проверки при работающем сервере:

```sh
python3 tests/http_smoke.py http://127.0.0.1:8765
```

Тест временно меняет звёздочку одного кандидата, восстанавливает её и создаёт тестовый CSV-экспорт трёх строк. Это техническая проверка, не шорт-лист.

Фактические журналы, JSON-проверки и снимок интерфейса находятся в `reports/`. Подробные результаты — `reports/REPORT.md`. Прототип не был доступен среди приложенных файлов; проект реализован по текстовому заданию.
