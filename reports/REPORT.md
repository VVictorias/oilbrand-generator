# Отчёт о полном переборе Oilbrand

Дата выполнения: 3 ноября 2026 года. Прототип не был доступен в приложениях к чату; реализация основана на текстовом техническом задании.

Сохранены **все 23 847 260 допустимых названий** в `data/brands.sqlite`. Шорт-листы, рейтинги, случайная выборка и лимит числа кандидатов не применялись.

Готовая база с индексами: **6 091 849 728 байт**, приблизительно 6,09 GB / 5,67 GiB. SHA-256: `database.sha256`. Конфигурация: `../config/rules.json`, её неизменяемая копия и стоп-слова — в SQLite. Признак завершения `metadata.status = complete`, завершены все 78 блоков.

## Применённые правила

Гласные AEIOU, Y — согласная. Q/W/X/J запрещены. Максимум две гласные, две согласные и две одинаковые буквы подряд. Списки запрещённых сочетаний, запрещённых окончаний и стоп-словарей пусты: пользователь не передал конкретные элементы. Поддержка этих правил реализована и протестирована, но произвольные дополнительные запреты не добавлялись. Список мягко отмечаемых окончаний также пуст.

Ноль в строке одинаковых букв не означает отсутствие фильтра: при исходных лимитах три одинаковые буквы раньше отклоняются правилом гласных или согласных. Причины не пересекаются в этой таблице, сумма равна полному пространству. Каждый фильтр проверен также отдельно на тестовых конфигурациях.

## Алгоритм и сохранность

Обход дерева префиксов выполняется детерминированно в порядке A–Z для каждой длины. Нарушивший жёсткое правило префикс исключает всё поддерево; его размер точно вычисляется степенью 26. Тем самым учитывается каждое из 321 254 128 исходных имён, хотя недопустимые строки не требуется материализовать. Ни одна допустимая ветка не отсекается из-за редкости сочетаний, звучания, транскрипции или субъективных критериев.

В базе — одна строка на допустимое имя. Уникальный индекс имени исключает дубликаты. ID кодирует длину и позицию в исходном пространстве, и это соответствие проверено для всех строк. Память ограничена текущей строкой, настройками, подключённым стоп-словарём и кэшем SQLite; кандидаты не накапливаются в коллекции.

78 блоков — длина × первая буква. Checkpoint и данные каждого блока находятся в одной SQLite-транзакции. Проверен сценарий: первый блок зафиксирован, второй аварийно прерван SQL-ошибкой, его частичные строки отсутствуют; после удаления искусственного сбоя запуск успешно продолжен. Повтор завершённого запуска не добавляет строк. Изменение конфигурации при попытке продолжения отклоняется.

## Анализ и интерфейс

Для всех имён сохранены количество гласных/согласных, C/V-структура, побуквенная русская транслитерация, приблизительные слоги по группам гласных, повторяющиеся буквы и биграммы, мягкие предупреждения об окончаниях и фонетические признаки. Они не участвуют в удалении.

Локальный интерфейс использует SQLite и курсорную пагинацию. Доступны точный поиск и подстрока, длина, префикс/суффикс, количества гласных/согласных, структура, слоги, исключения сочетаний/окончаний, фонетические признаки, сортировка, звёздочки, отдельное избранное, выделение строк. Фильтры объединяются. Запросы параметризованы, поля сортировки заданы белым списком.

Экспорт всей выборки выполняется потоково в фоне и не зависит от текущей страницы. CSV автоматически делится по настраиваемому числу строк. В браузере проверен экспорт трёх выделенных имён в две части; HTTP-тест дополнительно скачал обе части и сверил точный набор имён. Эти тестовые файлы в `../exports/` не являются шорт-листом.

Изменение поисковых фильтров не требует генерации. Для ослабления первоначальных жёстких запретов нужна новая база, потому что отвергнутые строки не сохраняются. Побуквенная транскрипция и число групп гласных — приближения, а не лингвистическая экспертиза. Проверка доменов и товарных знаков не выполнялась.

## Проверки и доказательства полноты

1. Независимый подсчёт допустимых имён динамическим программированием совпал с фактическим количеством по каждой длине.
2. SQL-проверка полной таблицы: 0 строк с нарушением заданных правил, 0 точных стоп-совпадений.
3. SQLite `PRAGMA integrity_check`: `ok`, включая уникальный индекс имён.
4. Число завершённых блоков — 78; сумма raw — 321 254 128; сохранённые строки и суммы accepted совпали.
5. Дополнительный независимый нативный аудит заново классифицировал буквы всех **23 847 260** строк, проверил C/V-структуру, количество гласных/согласных, оценку слогов, ранг ID, длину, первую/последнюю букву, перевёрнутое имя и жёсткие ограничения: **0 ошибок**, **8,99 с**.
6. 9 автоматических тестов, включая подслучаи всех фильтров, пройдены. Полный набор допустимых четырёхбуквенных имён сравнен как множество с независимым перебором; настройки ограниченного алфавита дополнительно исчерпывающе проверены на длинах 4–6.
7. HTTP-тесты и ручная проверка браузером: комбинированные фильтры, пагинация, точный поиск, буквальная обработка SQL-подобного ввода, подстрока/суффикс/количества, избранное с восстановлением исходного состояния, токен локальных изменений, фоновый экспорт, разбиение и скачивание CSV — пройдены.

Уникальность, принадлежность каждой строки допустимому множеству и совпадение размера этого множества с независимым расчётом совместно подтверждают отсутствие пропущенных допустимых комбинаций для сохранённой конфигурации.

## Производительность

Среда: macOS ARM64, Python 3.14.9, Apple clang 21.0.0, Python SQLite 3.50.4. Точные сведения сохранены в `environment.json`.

| Этап | Время |
|---|---:|
| Нативная генерация с анализом и записью всех прошедших строк | 30,1185 с |
| Полный запуск, включая индексы и ANALYZE | 110,9735 с |
| Из них индексация и завершение (разность замеров) | около 80,86 с |
| Обход и жёсткая фильтрация без записи, отдельный запуск | около 0,35 с |
| Полная основная проверка SQLite/SQL/независимого количества | 133,77 с |
| Дополнительный построчный нативный аудит | 8,99 с |

В фазе генерации — около 792 тыс. сохранённых строк/с, эквивалентный охват исходного пространства — около 10,67 млн комбинаций/с с учётом математически отсечённых поддеревьев. Это не утверждение о физическом создании 321 млн строк.

Узкое место — запись и индексы. Один писатель SQLite не требует межпроцессной передачи десятков миллионов строк; распараллеливание генератора не включалось. Сравнительный замер многопроцессного писателя не проводился; ускорение от него не заявляется. HTTP обслуживается потоками, экспорт выполняется фоновым работником.

Замеры отражают конкретный компьютер и дисковый кэш. Комбинированные запросы по редким подстрокам, точный подсчёт сложной выборки и экспорт десятков миллионов строк могут сканировать всю таблицу. Интерфейс сообщает о выполнении запроса; экспорты не имеют лимита результатов.
